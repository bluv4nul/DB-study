# Docker Practice

В этом проекте я последовательно разворачивал FastAPI-приложение с разными вариантами хранения данных. Каждая итерация находится в отдельной папке и запускается через свой `docker-compose.yml`.

## Итерация 1

Папка: `iteration-1`

В первой итерации приложение работает с SQLite. База хранится в файле `./db/data.sqlite`, а для просмотра данных добавлен отдельный веб-инструмент `sqlite-web` на порту `8080`. FastAPI доступен на порту `8000`.

Запуск:

```bash
cd iteration-1
docker compose up --build
```

## Итерация 2.1

Папка: `iteration-2.1`

Во второй итерации я переписал FastAPI с SQLite на MySQL. MySQL запускается отдельным сервисом, параметры подключения вынесены в `.env`, а данные сохраняются в именованном томе `mysql-data`.

Запуск:

```bash
cd iteration-2.1
docker compose up --build
```

## Итерация 2.2

Папка: `iteration-2.2`

В этой итерации я подключил альтернативную серверную БД по варианту - CouchDB. FastAPI работает с CouchDB через REST API, а задачи сохраняются как JSON-документы. Параметры подключения находятся в `.env`, данные CouchDB сохраняются в томе `couchdb-data`.

Запуск:

```bash
cd iteration-2.2
docker compose up --build
```

## Основные эндпоинты

Во всех итерациях используются одинаковые основные маршруты FastAPI:

- `GET /api/tasks` - получить список задач;
- `POST /api/tasks` - добавить задачу;
- `GET /api/tasks/{task_id}` - получить задачу по id;
- `PUT /api/tasks/{task_id}` - обновить задачу;
- `PATCH /api/tasks/{task_id}/toggle` - переключить статус выполнения;
- `DELETE /api/tasks/{task_id}` - удалить задачу;
- `GET /api/stats` - получить статистику.

Остановить контейнеры в любой итерации можно командой:

```bash
docker compose down
```
